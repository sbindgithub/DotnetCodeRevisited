# Azure App Service Logs

## Purpose
App Service logging helps diagnose runtime issues, monitor traffic, and debug failures in web apps/APIs.

---

## Types of Logs

### 1. Application Logs
- Logs generated by your code (ILogger, Console, etc.)

Levels:
- Trace
- Debug
- Information
- Warning
- Error
- Critical

Config:
- Enable in App Service → "App Service logs"
- Choose storage:
  - File System (temporary)
  - Blob Storage (persistent)

---

### 2. Web Server Logs (HTTP Logs)
- Captures incoming HTTP requests

Includes:
- Request URL
- Status code (200, 500, etc.)
- Response time
- Client IP

Used for:
- Traffic analysis
- Debugging failed requests

---

### 3. Detailed Error Messages
- HTML error pages for failed requests (4xx/5xx)

Used in:
- Debugging startup or runtime issues

⚠️ Not recommended in production (security risk)

---

### 4. Failed Request Tracing (FREB)
- Captures detailed trace for failed requests

Used for:
- Diagnosing slow or failed requests
- Deep IIS-level troubleshooting

---

### 5. Deployment Logs
- Logs from CI/CD deployments

Sources:
- Azure DevOps
- GitHub Actions
- Zip deploy

---

## Where Logs Are Stored

### Option 1: File System
- Temporary (auto-deleted after ~12 hours)
- Good for quick debugging

### Option 2: Blob Storage
- Persistent
- Recommended for production diagnostics

### Option 3: Application Insights (Preferred)
- Centralized logging
- Query using KQL
- Correlation across services

---

## How to Enable (Portal)

App Service → Monitoring → App Service logs

Enable:
- Application logging
- Web server logging
- Detailed errors (optional)
- Failed request tracing (optional)

---

## Log Streaming (Real-Time)

Use:
- Azure Portal → Log Stream
- CLI:
  az webapp log tail

Used for:
- Live debugging

---

## Production Best Practices

- Use Application Insights instead of file logs
- Set log level to:
  - Information (default)
  - Warning/Error for Microsoft logs
- Avoid Debug/Trace in production

---

## Common Problems

### Logs Missing
- Logging not enabled
- App Insights not configured

### Logs Lost
- Using file system (temporary storage)

### High Cost
- Too many logs (low log level)

---

## Architect-Level Thinking

You must answer:

### Q1: How do you debug a production issue?

- Check Application Insights
- Query failed requests
- Correlate logs using Operation Id

---

### Q2: Why not rely on App Service file logs?

- Not persistent
- Not scalable
- No cross-service visibility

---

### Q3: How do you trace a request end-to-end?

Client → App Service → Database → External API

Use:
- Correlation ID
- Distributed tracing (App Insights)

---

## Summary

App Service Logs = Local diagnostics  
Application Insights = Production-grade monitoring

Use both appropriately.
